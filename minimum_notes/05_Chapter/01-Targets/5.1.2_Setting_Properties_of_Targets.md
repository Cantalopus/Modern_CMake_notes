# Setting Properties of Targets... 
Targets have properties that work in a similar way to fields of C++ objects. Some properties are meant to be modified, others are read-only. CMake defines a large list of "known properties" that are available depending on the type of the target(executable, library, or custom). You can add your own properties of a target:
```cmake
get_target_property(<var> <target> <property-name>)
set_target_properties(<target1> <target2> ... 
                      PROPERTIES <prop1-name> <value>
                      <prop2-name> <value2> ...)
```  
To print target property on the screen, we first need to store in in the variable \<var\> and then message it to the user. Reading of the properties has to be done one by one; setting properties on a target allows us to specify multiple properties at the same time, on multiple targets.

    Important note

        The concept of properties isn't unique to targets; CMake supports setting properties of other scopes as well: GLOBAL, DIRECTORY, SOURCE, INSTALL, TEST, and CACHE. To manipulate all kinds of properties, there are general get_property() and set_propert() commands. In some projects, you'll see these low-level commands used to do exactly what the set_target_properties() command does, just with a bit more work:

Generally, it's better to use as many high-level commands as you can. In some cases, CMake offers short-hand commands that come with additional mechanisms. For example, add_dependencies(\<target\> \<dep\>) is a shorthand for appending dependencies to the MANUALLY_ADDED_DEPENDENCIES target property. In this case, we can query it with get_target_property() exactly as with any other property. However, we can't use **set_target_properties()** to change it(it's read only), as CMake insists on using the **add_dependencies()** command to restrict operations to appending only.
