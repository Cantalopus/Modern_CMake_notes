# Loops... 
We can use either a **while()** loop or a **foreach()** loop to repeatedly execute the same set of commands. Both of these commands support loop control mechanisms:
- The **break()** command stops the execution of the remaining block and breaks from the en-closing loop.
- The **continue()** command stops the execution of the current iteration and starts at the top of the next one.
```text
Note that no local variable scope is created in any of the loop blocks.
```

## while()
while() loops have to be closed with the **endwhile()** command. 
```cmake
while(<condition>)
  <commands>
endwhile()
```

## foreach()
The simplest form of **foreach()** is meant to provide a C++-style for loop:
```cmake
foreach(<loop_var> RANGE <max>)
  <commands>
endforeach()
```
CMake will iterate form 0 to \<max\>(inclusive). If we need more control, we can use the second variant, providing \<min\>, \<max\>, and optionally, \<step\>. All arguments must be non-negative integers, and \<min\> has to be smaller than \<max\>:
```cmake
foreach(<loop_var> RANGE <min> <max> [LISTS <lists>] [ITEMS <items>])
```
However, foreach() shows its true colors when it is working with lists:
```cmake
foreach(<loop_var> IN [LISTS <lists>] [ITEMS <items>])
```
CMake will retrieve elements from one or more specified \<lists\> list variables, as well as a list of \<items\> values defined in-line, and put them in \<loop_var\>. Then, it will execute all commands for each item in the list. You can choose to provide only lists, only values, or both:

**minimum_notes/02_Chapter/07_Control_Structures/foreach.cmake**
```cmake
set(MyList 1 2 3)
foreach(VAR IN LISTS MyList ITEMS e f)
  message(${VAR})
endforeach()
```
Output... 
```bash
1
2
3
e
f
```

Or, we can use a short version(skipping the **IN** keyword) for the same result:
```cmake
foreach(VAR 1 2 3 e f)
```
Since version 3.17, foreach() has learned how to zip lists(ZIP_LISTS):
```cmake
foreach(<loop_var>... IN ZIP_LISTS <lists>)
```
The process of zipping lists involves iterating through multiple lists and operating on corresponding items that have the same index. Let's look at an example:

foreach.cmake
```cmake
set(L1 "one;two;three;four")
set(L2 "1;2;3;4;5")
foreach(num IN ZIP_LISTS L1 L2)
  message("word=${num_0}, num=${num_1}")
endforeach()
```
Output... 
```bash
word=one, num=1
word=two, num=2
word=three, num=3
word=four, num=4
word=, num=5
```
CMake will create a num_<N> variable for each list provided, which it will fill with items from each list.

You can pass multiple variable names(one for every list) and each list will use a separate variable to store its items:
```cmake
foreach(word num IN ZIP_LISTS L1 L2)
  message("word=${word}, num=${num}")
```
Both examples on ZIP_LISTS will produce same output:
```bash
word=one, num=1
word=two, num=2
word=three, num=3
word=four, num=4
word=, num=5
```
Notice, that in the event that the item counts between lists vary, variables for the shorter lists will be empty, as you can see above. 

Also, loop variables are restricted to the local scope of the loop.
