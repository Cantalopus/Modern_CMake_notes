# Understanding Control Structures
Control structures come in 3 categories.. 
- conditional blocks
- loops
- command definitions

## Conditional blocks.. 
The only conditional block in CMake is the if() command. All conditional blocks have to be closed with an endif() command, and may have any number of elseif() commands and one optional else() command. 
```cmake
if(<condition>)
  <commands>
elseif(<condition>) # optional block, can be repeated
  <commands>
else()              # optional block
    <commands>
endif()
```
```text
Note that no local variable scope is created in any of the conditional blocks. 
```

## Logical Operators... 
The if() conditions suport the NOT, AND, and OR logical operators
- **NOT** \<condition\>
- \<condition\> **AND** \<condition\>
- \<condition\> **OR** \<condition\>

Also, nesting of conditions is possible with matching parentheses(()). Starts evaluation from innermost parentheses:
```cmake
(<condition>) AND (<condition> OR (<condition>))
``` 

#### Keep in mind... 
That... 
```cmake
set(BAZ FALSE)
set(QUX "BAZ")
if(${QUX})
```
First, it will evaluate ${QUX} to BAZ, which is a recognized variable, and this in turn is evaluated to a string containing five characters spelling FALSE. Strings are considered *Boolean true* only if they equal any of the following constants..
```text
case-insensitive: ON, Y, YES, TRUE, non-zero number
```
Here's what's happening.. 
```text
${QUX} -> BAZ -> FALSE
```

#### Another catch to be mindful of... 
```cmake
set(FOO BAR)
if(FOO)
```
This conditional evaluates to *TRUE*. Unlike quoted arguments, FOO won't be evaluated to BAR to produce an if("BAR") statement(which would be false). Instead, CMake will only evaluate if(FOO) to false if it is any of the following constants.

case insensitive: 
- OFF, NO, FALSE, IGNORE, or NOTFOUND
- A string ending with -NOTFOUND
- An empty string
- Zero

So, an undefined variable will evaluate to false:
```cmake
if(CORGE)
```
When a variable is defined beforehand, the scenario changes and the condition evaluates to true:
```cmake
set(CORGE "A VALUE")
if(CORGE)
```
```text
Important note!

    If you think that the recursive evaluation of unquoted if() arguments is confusing, wrap variable references in quoted arguments: if("${CORGE}"). This will result in argument evaluation before the provided argument is passed into the if() command, and the behavior will be consistent with the evaluation of strings.
```

In other word, CMake assumes the the user passing a variable name to the if() command is asking whether the variable is defined with a value **that does NOT evaluate to Boolean false**. To explicitly check whether the variable is defined or not(and ignore its value), we can use the following:
```cmake
if(DEFINED <name>)
if(DEFINED CACHE{<name>})
if(DEFINED ENV{<name>})
```
