## Command invocations
Command names aren't case sensitive, but convention is snake_case...
```cmake
    message("hello" world)
#   ^^^^^^^ ^^^^^^^^^^^^^^
#    name      argument
```
Each line of source code can only contain one command. 
```cmake
command(argument1 "argument2" argument3) # comment
command() #[[ multline
               comment #]]
```
Virtually every command relies on other elements of the language in order to function: variables,
conditional statements, and, most importantly, command-line arguments.


## Command arguments
- Bracket arguments
- Quoted arguments
- Unquoted arguments

### minimum_notes/02_Chapter/01-arguments/bracket.cmake
```cmake
message([[multiline
    bracket
    argument
]])
message([==[
    because we used two equal-signs "=="
    this command receives only a single argument
    even if it includes two square brackets in a row
    { "petsArray" = [["mouse","cat"],["dog"]] }
]==]) 
```
In the preceding example, we can see different forms of bracket arguments. Note how putting
closing tags on a separate line in the first call introduces an empty line in the output:
```linux
:~/Modern_CMake_notes$ cmake -P ./minimum_notes/02_Chapter/bracket.cmake
multiline
bracket
argument

    because we used two equal-signs "=="
    this command receives only a single argument
    even if it includes two square brackets in a row
    { "petsArray" = [["mouse","cat"],["dog"]] }
```
The second form is useful when we're passing text that contains double brackets( ]] )(highlighted
in the code snippet), as they won't be interpreted as marking the end of the argument.


### Quoted argument
These will expand like C or C++ strings, including whitespace. Likewise, quotes within the string
must be escaped with a backslash, \". Other well known escape sequences are supported as well:
\\\\ denotes a literal backslash, \t is a tab character, \n is a newline, and \r a carriage return. 

### minimum_notes/02_Chapter/01-arguments/quoted.cmake
```cmake
message("1. escape sequence: \" \n in a quoted argument")
message("2. multi... 
    line")
message("3. and a variable reference: ${CMAKE_VERSION}")
```
Output... 
```linux
~/Modern_CMake_notes$ cmake -P ./minimum_notes/02_Chapter/quoted.cmake
1. escape sequence: " 
 in a quoted argument
2. multi... 
line
3. and a variable reference: 4.3.3
```

### Unquoted arguments
Unquoted arguments evaluate both escape sequences and variable references. 
(;)Semicolons in CMake are list delimiters.
```text
argum\ ent\;1   arg;ume nts
^^^^^^^^^^^^^   ^^^ ^^^ ^^^
a single arg     three args
 ```
Unquoted arguments cannot contain unescaped *quotes("), hashes(#), and backslashes (\\). Parentheses, (), are allowed only if they form correct, matching pairs. 

Here are some examples that demonstrate these rules.. 
### minimum_notes/02_Chapter/01-arguments/unquoted.cmake
```cmake
message(a\ single\ argument)
message(two arguments)
message(three;separate;arguments)
message(${CMAKE_VERSION}) # a variable reference
message(()()())           # matching parentheses
```
Output... 
```text
$ cmake -P ch02/01-arguments/unquoted.cmake
a single argument
twoarguments
threeseparatedarguments
3.16.3
()()()
```

### Example: command containing unquoted arguments... 
```cmake
project(myProject VERSION 1.2.3)
```
