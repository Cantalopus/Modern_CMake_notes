# Using Cache Variables
Presistent variables stored in a CMakeCache.txt file, in your build tree. They contain information gathered during the **configuration stage** of your project. They originate from the system(path to compilers, linkers, tools, and others) and from the user, provided through the GUI or from the command line with the -D option. 

**Cache variables are not available in scripts; they only exist in projects**

```text
Important note!

    ${<name>} is the normal variable-reference syntax, right? So, when ${MY_REF} is evaluated, CMake first looks for a normal variable named MY_REF. If it cannot find one, CMake, in turn, looks for a cache variable named MY_REF. 
```
```cmake
# Example
"${MY_REF}"       # normal variable first, then cache variable fallback
"$CACHE{MY_REF}"  # explicitly a cache variable
``` 

Cache variables can be explicitly referenced with the $CACHE{<name>} syntax and defined with a special form of the set() command:
```cmake
set(<variable> <value> CACHE <type> <docstring> [FORCE])
```
### Example... 
```cmake
set(FOO "BAR" CACHE STRING "interesting value" FORCE)
```

In contrast to the set() command for normal variables, extra arguments are necessary for cache variables: <type> and <docstring>. This is because these variables can be configured by the user, and the GUI requires this information to display them appropriately. 

The folling types are accepted:
- BOOL: A Boolean on/off value. 
- FILEPATH: A path to a file on a disk. 
- PATH: A path to a directory on a disk.
- STRING: A line of text
- INTERNAL: A line of text. The internal entries may be used to store variables persistently across runs. Use of this type implicitly adds the FORCE keyword.
